# 10 · 测试、CI 与代码质量

## 工具链
- Vitest：单元与集成测试。
- Playwright：浏览器 E2E、关键响应式检查与真实路由测试。
- ESLint + Prettier + TypeScript `strict`。
- GitHub Actions：PR 检查、测试、构建、依赖漏洞扫描与契约检查。
- Turborepo 根据包依赖图安排任务、并行执行与缓存。

## PR 必须通过
1. 格式、Lint、类型检查。
2. 单元/集成测试。
3. Playwright 关键流程。
4. 构建与包依赖边界检查。
5. OpenAPI 生成和契约差异检查。
6. 注册表、Seed 与数据库模型一致性检查（测试环境）。
7. 严重且可利用依赖漏洞扫描。
8. 关键隐私网络审计与 CSP/响应头检查。
9. 关键路由真实 HTTP 404 检查。
10. 关键页面性能与构建体积预算检查。

一般安全检查失败可告警并由负责人决定；严重且可利用依赖漏洞仍阻止合并。

## 性能预算
- 分别为首页、分类页、工具页和重型引擎建立预算。
- 先在基线环境测量，再由根 Agent提交建议阈值给用户确认；禁止凭空设定未经测量的阈值。
- 大型 WASM、模型和媒体引擎必须按需加载并单独计入预算。

## 测试数据
- 使用隔离测试数据库和可重建测试数据。
- E2E 不得连接生产数据库或触发生产配置修改。
- 测试失败禁止合并；生成报告并记录未覆盖风险。
