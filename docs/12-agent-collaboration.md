# 12 · Agent 与 Subagent 协作

> 状态：**生效中**。当前协作方式已在阶段 3/4 实际使用：根 Agent 冻结接口与文件边界，多个实施 Agent 并行、零重叠，根 Agent 集成与验收。

## 1. 角色

- **根 Agent**（当前：Deepseek-V4.1-Flash High）：规划、接口裁决、文件所有权划分、集成、验收、冲突处理、文档核验。
- **实施 Agent**（当前：Deepseek-V4.1-Flash High）：在获派文件范围内实现、测试、报告；不得越界，不得自行改契约。
- 模型与推理强度按当前任务明确指示执行；需要调整由根 Agent 协调，不自行覆盖约定。
- 根 Agent 不得把未确认的架构决策伪装成用户已批准。

## 2. 分支与工作区

- 每个任务使用独立分支或 Worktree；当前主分支为 `main`，阶段成果以单次提交落地。
- 派发前必须定义：目标、禁止事项、文件所有权、依赖与冻结接口、验收标准、必须运行的命令。
- 不同 Agent 不得并行修改同一契约文件或同一资源聚合入口（如 `i18n/resources/index.ts`）。
- 共享工作目录中先看 `git status` 与当前 diff；不得覆盖或撤销他人修改。

## 3. 派发模板

每个任务必须包含：

1. 目标与不做事项。
2. 允许修改的文件/目录（逐项列出）。
3. 依赖模块与已冻结接口。
4. 具体实现要求（含数据形状、命名、i18n 键）。
5. 必须运行的测试/类型检查命令。
6. 验收标准与已知限制。
7. 风险、假设与待决问题。
8. 文档更新要求（若无，明确写“无需更新”）。

阶段 3/4 的实际派发示例：catalog、i18n、web-shell、web-pages、server 五个 Agent 文件零重叠；根 Agent 先写 `contracts` 与包骨架，再派发依赖任务。

## 4. 集成流程

1. 根 Agent 先落地共享契约与包骨架，再派发依赖任务。
2. 实施 Agent 在范围内实现、运行自己包的类型检查与测试、报告实际输出。
3. 根 Agent 检查变更范围、接口兼容、重复实现、隐私边界、i18n 键使用、测试真实性。
4. 根 Agent 负责跨包接线（如 `apps/web` 依赖声明、构建脚本、SSR 配置）与冲突解决。
5. 全量门禁 `pnpm verify`（format/lint/typecheck/test/build/check:tools/check:i18n/HTTP）通过后提交；不得跳过检查。
6. 生产部署与敏感变更仍须用户批准。

## 5. 自主权限

Agent 可自主：规划、并行开发、测试、修复、文档更新、隔离环境集成。

不得未经批准：生产部署、生产数据库迁移、破坏性数据操作（含清空本地/生产数据）、公网安全配置变更、扩大产品范围（如新增真实工具清单）。

## 6. 报告要求

实施 Agent 结束必须报告：

- 改动文件清单。
- 实际执行的命令与输出尾部（不得伪报）。
- 未执行/未覆盖项。
- 偏差、风险与需要根 Agent 决策的问题。

根 Agent 在最终回复中给出：提交 hash、逐项验收对照、HTTP 验收结果、已知限制、下一步门槛。
