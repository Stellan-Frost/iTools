# 09 · PWA、离线与缓存

> 状态：**未实现（阶段 10）**。当前没有 Service Worker、离线缓存、更新提示或 Cache Storage 管理。

## 离线能力
- 预缓存全部工具代码和基础资源。
- 重型 WASM、模型与媒体引擎首次成功下载后缓存；未缓存引擎不能保证离线执行。
- 离线时完全依赖本地缓存，继续展示和打开上次可用的工具；不额外区分目录新鲜度与缓存完整性。
- 目录动态数据在线时按既定策略重新验证；离线时使用本地缓存。
- 刷新/关闭页面时未完成任务标记失败或丢弃，不承诺浏览器关闭后继续执行。

## 缓存策略（必须按既定选择实现）
- 用户选择：**每次更新后不残留任何旧缓存**（D36）。执行顺序固定为：新版本在版本化 cache（`itools-precache-<buildId>`）内完整下载 → 全部成功才 activate → activate 时清空**全部**旧缓存（含重型引擎）。顺序不得改为「先清空再下载」。
- **重型引擎随壳层一起清空**（D36）：更新成功后，引擎类工具在重新下载前**不能离线执行**，UI 必须把该工具标记为「需联网重新下载」，不得提示「仍可离线」。
- 不保留上一版本（D36）：版本回退只走服务端部署回滚；客户端另提供「修复安装」（清空并全量重下当前版本），只用于修复半损坏缓存。
- 不得清理 IndexedDB 用户数据；应用 Cache Storage 与 IndexedDB 必须分离管理。
- 更新由用户确认；若有运行任务，提示中断风险，禁止静默刷新。
- 下载失败恢复路径（D36）：放弃本次安装、旧缓存与旧版本保持完整、提示「更新未完成，仍使用上一版本」并提供重试；同一 buildId 连续失败 2 次后不再自动提示，改为设置项内手动触发。**不得声称更新期间仍保有旧缓存**——旧缓存只在「新版本未激活」时保留。
- 静态资源尽可能使用内容哈希；动态 API、认证响应和敏感数据不得进入共享 CDN/Service Worker 缓存。
- CDN 目录缓存可较长并自然过期；服务端直达工具路由仍须查询启用状态并返回真实 HTTP 404。

## 必测
- 首次安装、离线启动、已访问/未访问重型引擎、更新提示、用户拒绝更新、更新下载失败、运行任务中更新、旧缓存清理、IndexedDB 数据不受缓存清理影响。
- D36 追加：更新下载失败后**离线启动仍成功且版本号未变**；更新成功后旧 buildId 的 cache 数量为 0；引擎被清除后工具显示「需联网重新下载」；「修复安装」可恢复半损坏缓存；连续失败 2 次后不再自动提示。
