## 必须由根 Agent 明确处理的决策冲突
### D-01：IndexedDB 清空重建 vs 长期保留
- 用户在第 108 题选择结构变化时清空本地数据库重建。
- 同时要求任务记录与结果长期保留，并提供完整导出/导入。
- 风险：生产清库会造成不可逆数据损失。
- 处理：不得静默执行生产清库。实现前将环境范围、提示/确认、导出恢复方式提交用户批准；或者提出兼容迁移替代方案。

### D-02：清空全部应用缓存 vs 更新期间离线可用
- 用户在第 110 题选择每次更新清空所有应用缓存并重新下载。
- 风险：清理后下载失败会暂时失去离线能力。
- 处理：明确更新失败恢复路径；不得清理 IndexedDB。按用户选择实施时须在更新界面说明风险。

### D-03：CDN 长缓存 vs 工具停用状态
- 用户选择尽可能长缓存并依赖自然过期。
- 仍必须满足直达工具 URL 服务端检查数据库状态并返回真实 404。
- 处理：缓存只能造成目录展示短暂滞后，不能绕过服务器路由校验；明确 SSR HTML 是否可缓存及其 TTL。

### D-04：安全告警 vs 硬性门禁
- 一般安全检查失败：告警，由负责人决定。
- 严重且可利用依赖漏洞：阻止合并。
- 处理：CI 明确区分 warning 与 blocking rules。

### D-05：单管理员
- 不实施多管理员协作编辑或复杂冲突协调。
- 保留数据库事务与基本条件更新，防止重复提交、旧页面覆盖新值。

## 已知运维风险
- 备份存放在同一生产服务器的独立磁盘/目录，无法抵御整机/站点级灾难；这是已选方案，不得描述为异地灾备。
- 不做定期恢复演练，直到真实故障才验证恢复能力。
- RTO/RPO 均为 24 小时目标，实际达成尚待验证。
- 固定速率限制不含渐进延迟；不得实现永久账户锁定。
- 安全检查通常告警而非一律阻断，但既定严重漏洞门禁不可绕过。
