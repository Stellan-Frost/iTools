## 3. 决策记录

### 已决

| 编号 | 决策 |
| --- | --- |
| D05 | 只做唯一管理员，不开放注册、不做多管理员协作。 |
| D06 | 阶段 3/4 只验收不依赖数据库与任务运行时的部分；数据库启用状态、Seed 一致性、结果持久化在阶段 7 后验收。 |
| D08 | 分类固定为 `audio/image/video/text/other`；阶段 2 的预览分类退役。 |
| D09 | 工具目录由代码注册表提供；数据库在阶段 7 接入后仍保持同一 URL 与可用性规则。 |
| D10 | 工具 URL 必须包含分类；分类不匹配、停用、不存在均 404，不做重定向。 |
| D11 | `/` 302 → `/zh-CN`；非根尾斜杠 308。 |
| D12 | 语言切换保留当前路由。 |
| D13 | 任务页、管理页 `noindex`，robots 禁止抓取，不进 Sitemap。 |
| D14 | HTML `max-age=0, must-revalidate`；404 `no-store`；Sitemap/robots `max-age=300`；assets 一年 immutable。 |
| D15 | SSR 必须把 app-core、adapter、`m3-expressive-react`、`@material/material-color-utilities` 放入 `ssr.noExternal`。 |
| D17 | 首页首屏保留全局搜索；`openSearch` 纳入 `AppNavigation` 上下文。 |
| D18 | 服务端 dev 使用 `node --watch-path=./src`；不得监听全仓库（Vite 写 `.vite` 会无限重启）。 |
| D19 | 工具可用性三态：`preview / implemented / disabled`，取代 `enabled: boolean`。 |
| D20 | 预览页 200 + `noindex`、不进 Sitemap；停用页 404。 |
| D21 | 导航、搜索、卡片可展示预览工具，但必须带“预览”徽标。 |
| D22 | 注册表是工具元数据与可用性的唯一来源；`app-core/catalog` 只保留分类与样本任务。 |
| D23 | 阶段 4 先建全局框架，不发布真实工具；执行契约用测试 fixture 验证，执行 UI 留到首个真实工具。 |

## 4. 阶段验收记录要求

每个阶段结束必须记录：

1. 阶段编号、目标、范围与非范围。
2. 修改文件清单。
3. 实际执行的命令与结果（含测试数量、失败项）。
4. 验收标准逐项状态（通过/部分/延后）。
5. 证据位置（脚本、日志、截图或 URL）。
6. 未解决问题与已知限制。
7. 是否允许进入下一阶段。

缺少可复现证据即视为未验收；不得用“已完成”口头声明替代。
