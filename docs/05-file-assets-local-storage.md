# 05 · 文件资产与浏览器本地存储

## 统一资产模型
至少区分 `source`、`intermediate`、`result`；每项有稳定 ID、文件名、MIME 提示、大小、创建时间、关联 task ID、引用关系和持久化状态。
- Blob 由统一 IndexedDB repository 管理；工具不得直接创建自有数据库表或绕过仓储层。
- 临时 Object URL 由共享生命周期管理器创建并释放，不得当作持久化地址。
- 结果与源文件分开存储；源文件清理不得删除仍被任务引用的文件或长期保留的结果。

## 输入安全与资源预算
- 检查扩展名、MIME 提示、文件大小；可行时检查签名，并以真实解析结果作为格式有效性的重要依据。
- 每个工具声明允许格式、最大输入、必要 API、预计内存和计算等级。
- 执行前检查浏览器能力与资源限制；不满足时保留入口、解释缺失能力并禁用执行，不上传文件或自动转服务器处理。
- 对大型文件优先使用流式/分块处理；需要缓冲时纳入内存预算。

## IndexedDB 保留策略
- 任务记录与处理结果长期保留。
- 源文件默认保留 7 天；用户可在存储管理中调整保留期限。
- 清理前检查任务状态与引用关系，绝不删除正在使用的源文件。
- 存储接近配额时分级提示；申请持久化存储失败时继续使用并提示回收风险。
- 写入失败时不得自动删除已完成结果；处理部分写入回滚，不能把未持久化结果标记为完成。

## 数据导出与导入
- 提供完整本地归档：任务记录、处理结果、可选源文件，附归档格式版本。
- 导入前验证结构、引用、兼容性和配额；失败不能破坏现有数据。
- 不上传归档内容。
- 用户明确选择“清空并重建 IndexedDB”为已确认偏好，但生产升级清库可能造成永久数据丢失。实现前必须在验收决策中明确范围与确认流程；不得静默清空用户数据。

## 结构升级冲突（必须显式解决）
第 108 题选择结构变化时清空本地数据库；长期保留任务与结果、完整导出导入则要求数据可持续。这些要求存在冲突。根 Agent 不得自行假定生产清库已获批准；应提交影响说明并取得明确批准，或提出不丢数据的迁移方案。
