# 16 · 当前仓库审计与实现边界

> 更新：2026-10-19。此文记录当前可见代码和已有阶段证据；历史验收结果不是本轮重跑结果。阶段 0 最初发生在仅含文档的目录中，之后工作区与阶段 2 预览逐步建立。审计依据包括 `docs/00`–`15`、当前包清单、源码、脚本及 [阶段 1](17-stage-1-workspace.md)、[阶段 2](18-stage-2-design-system.md) 记录。

## 当前实现

仓库是 pnpm/Turborepo 工作区，目前只有三个包：

| 路径                             | 当前职责           | 现有内容                                                                                           |
| -------------------------------- | ------------------ | -------------------------------------------------------------------------------------------------- |
| `packages/contracts`             | 共享数据形状       | TypeBox API 错误/成功响应、资产引用、任务状态与记录、工具 manifest/definition、服务端环境 Schema。 |
| `packages/design-system-adapter` | MD3 组件和主题适配 | `m3-expressive-react` 组件公开入口、鸭青主题、字体与全局样式。                                     |
| `apps/web`                       | 阶段 2 浏览器预览  | React/Vite 的首页、分类、工具、任务、管理预览；目录、任务与结果均为样例数据。                      |

依赖方向为 `apps/web → design-system-adapter` 和 `contracts → typebox`；当前 Web 尚未依赖 contracts。详见各包的 `package.json` 与 [阶段 2 设计说明](18-stage-2-design-system.md)。

## 不可从现有代码推断为已实现的能力

- 没有 SSR、服务端应用、真实 URL 路由、国际化或 SEO 输出；`AppRoute` 是前端内存状态。
- 没有数据库、迁移、API 路由、OpenAPI、目录 Seed 或服务端持久化。
- 没有真实工具注册表、处理引擎、Worker/调度器、文件资产存储或 IndexedDB。
- 没有管理员认证/授权、PWA、CI 工作流或部署配置。
- 阶段 2 的搜索、工具条目、任务进度、结果和管理表单仅用于界面预览；刷新会丢失内存导航和主题状态。

`packages/contracts` 只定义契约形状，不实现这些契约背后的运行时。`ServerEnvironmentSchema` 是环境配置校验函数，不是服务器或数据库连接。
