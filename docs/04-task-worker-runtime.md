# 04 · 任务状态机、调度器与 Worker

## 统一状态机
状态：`queued`（排队中）、`preparing`（准备中）、`running`（运行中）、`cancelling`（取消中）、`completed`（已完成）、`failed`（已失败）、`cancelled`（已取消）。
- 只允许显式定义的状态转换；非法转换拒绝并测试。
- 只有结果成功提交到存储后才能标记 `completed`。
- 刷新/关闭页面时，未完成任务按既定规则标记失败或丢弃；不承诺浏览器关闭后继续执行。
- 页面内路由切换不取消任务；任务由全局调度器持有，不绑定单个 React 页面组件。

## 调度策略
- 全局 FIFO + 资源感知并发控制。
- 任务声明预计内存、输入大小、计算等级、引擎与并发需求；调度器检查全局和工具级预算。
- 允许轻量任务在不违反资源限制时先行执行，但不得突破总资源上限。
- 每个任务有稳定 task ID、统一进度事件、取消确认、错误结构与结果提交协议。
- 用户取消、失败或资源超限时，必须停止执行、释放资源并更新最终状态。

## Worker
- 共享 Worker 池 + 工具专属执行适配器。
- 重型 WASM/媒体引擎按需加载；不同引擎可用独立 Worker 类型。
- Worker 仅计算，不直接持久化任务或绕过调度器。
- 统一消息协议：`start`、`progress`、`complete`、`error`、`cancel`、`cancelled`。
- 对无法协作取消的任务，定义终止并重建 Worker 的策略。
- 任务队列和并发上限集中配置；工具不得自行创建无限 Worker 或自建队列。

## 错误
- 共用错误分类、稳定错误代码、用户可读消息、可选详情与恢复动作。
- 轻微提示用 Snackbar；输入错误就地显示；任务失败显示原因/代码/重试；严重问题使用对话框。
- 不把堆栈、内部路径或敏感参数暴露给普通用户。
