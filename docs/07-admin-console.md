# 07 · 管理后台

> 状态：**已实现（阶段 8）**：后端接口与后台界面均可用，`/{locale}/admin` 不再是内存预览。
> 已实现：`admin_credentials` 表、口令哈希、会话、Cookie、CSRF、限流、初始化/登录/登出、元数据编辑、启停、版本列表与回滚（`apps/server/src/admin/**`）。
> 界面包含初始化、登录、工具选择、双语文案编辑、上下架确认、版本历史与回滚；只有组件测试，**未做浏览器 E2E**。
> 阶段 8 的三项决策：**不给后台开放分类与图标编辑**（D29）、**元数据版本保留最近 50 版**（D30）、**初始化令牌来自环境变量 + 网页初始化页**（D31）。

## 权限模型
- 首期唯一管理员；不开放注册，不建设普通用户账户系统。
- 管理后台优先开发。
- 普通用户免登录，任务、偏好和结果保存在浏览器。
- 未来若需求变化需支持多管理员，另行提交架构变更；当前不实现多管理员协作编辑功能。

## 首次初始化与认证
- 首次管理员通过专用初始化页面创建；**部署时把一次性令牌注入环境变量 `ADMIN_SETUP_TOKEN`**，页面提交令牌 + 设置口令。
- 令牌只与内存中的环境变量比对，**不落库、不写日志**；初始化成功后入口永久关闭（再访问返回 409）。
- 未设置 `ADMIN_SETUP_TOKEN` 时初始化入口视为不存在，不允许任何创建路径。
- 服务端会话 + 安全 Cookie：HttpOnly、Secure、适当 SameSite、CSRF 防护、会话轮换、过期和主动撤销。
- 会话存 PostgreSQL；空闲 7 天失效，绝对有效期 30 天。
- 管理员密码重置只能通过需要服务器管理权限的专用恢复命令；撤销所有旧会话并记录安全事件；不开放公网恢复 API。
- 登录使用固定速率限制；不实现渐进延迟或永久账户锁定。
- 所有权限检查在服务端执行。

## 管理功能
- 工具启用/停用（只能下架或恢复注册表默认，不能启用不存在的实现）。
- 排序调整。
- 编辑工具名称、简介与中英文 SEO 元数据。
- 查看必要的工具状态与诊断信息。
- 元数据历史预览与一键回滚。
- 存储/目录状态与必要运行状态查看。
- **不可编辑分类与图标**（D29）：分类与图标属于工具身份，只由代码注册表决定；后台改动会让 URL 规则（分类必须匹配）与 `check:tools` 失效。
- 所有变更先校验 Schema、在必要时使用事务，并记录最小化结构化应用日志。

## 元数据版本
- 仅对可编辑的展示元数据保存版本快照；不建立全站独立审计表。
- 回滚必须检查目标版本、当前版本与字段合法性，防止覆盖更新内容。
- **保留策略（D30）**：每个「工具 + 语言」保留最近 50 个版本，按数量清理；当前生效版本永不被清理。
- 版本清理由统一维护调度器执行。

## UI
- 使用全站设计系统；中英文完整。
- 后台写操作必须显示明确结果和失败原因；破坏性操作需确认。

界面状态机（`apps/web/src/pages/admin/`）：

1. **加载**：并行请求 `GET /admin/setup` 与 `GET /admin/session`。
2. **初始化**：仅当 `available === true` 显示；令牌 + 口令 + 确认口令，本地校验 12 位最小长度与两次一致。
3. **登录**：不可初始化且未认证时显示；失败统一「口令错误」，429 显示限流提示。
4. **已登录**：工具列表 + 双语文案表单 + 排序 + 上下架（二次确认）+ 版本历史与回滚（二次确认）。
5. 任一业务请求返回 401 时回到登录态并提示会话过期。

## 口令恢复

```sh
cd apps/server
DATABASE_URL=postgresql://... node dist/cli/reset-password.js
# 或指定新口令（不推荐写进 shell 历史）
ADMIN_NEW_PASSWORD='...' DATABASE_URL=... node dist/cli/reset-password.js
```

未设置 `ADMIN_NEW_PASSWORD` 时生成 24 字节随机口令并**只打印一次**。命令会撤销全部旧会话；口令长度不足或管理员未初始化时以非零码退出且不写数据。

## 已实现的后端接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/v1/admin/setup` | 校验 `ADMIN_SETUP_TOKEN` + 设置口令，成功后自动登录；重复调用 409 |
| POST | `/api/v1/admin/session` | 登录（固定限流 5 次 / 15 分钟），成功轮换新 token |
| GET | `/api/v1/admin/session` | 当前会话信息 |
| DELETE | `/api/v1/admin/session` | 撤销当前会话并清除 Cookie |
| PATCH | `/api/v1/admin/tools/:toolId/metadata` | 双语文案 + 排序，写版本快照 |
| PATCH | `/api/v1/admin/tools/:toolId/availability` | 下架 / 恢复注册表默认 |
| GET | `/api/v1/admin/tools/:toolId/versions` | 版本列表（倒序） |
| POST | `/api/v1/admin/tools/:toolId/rollback` | 回滚，需携带 `expectedVersionId` 防覆盖 |

实现要点：

- 口令 `scrypt`（N=16384, r=8, p=1）+ 随机盐，`timingSafeEqual` 比较。
- 会话 token 32 字节随机，库中只存 sha256 哈希；空闲 7 天滑动、绝对 30 天封顶。
- CSRF 双提交：`itools_admin_csrf` 可读 Cookie + `x-csrf-token` 头，非 GET/HEAD 强制校验。
- 所有管理响应 `cache-control: no-store`；错误信封 `{ code, message, requestId }`，固定文案不泄露内部信息。

## 已知限制

- 会话 Cookie 的 `Max-Age` 在登录时固定为 7 天，后续请求只做服务端滑动续期，**浏览器端不会自动续期**：持续活跃超过 7 天仍需重新登录。
- CSRF token 不随会话轮换，生命周期与登录时下发的 Cookie 一致。
- 限流是进程内固定窗口，多实例部署时各自计数。
- 元数据写入是「读-改-写」跨多次仓储调用，**没有数据库事务**；并发编辑可能后写覆盖（回滚有 `expectedVersionId` 保护）。
- 版本快照按「工具 + 语言」记录三条文案；**排序与启停不进入版本历史**（D32）。
