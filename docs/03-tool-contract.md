# 03 · 工具注册契约与页面标准

## 注册表
每个工具必须在代码中注册，至少包含：
- `id`：稳定、唯一、不可随意更改。
- `category`、`routeKey`、`icon`、实现版本。
- 输入/输出 TypeBox 或共享 Schema 定义。
- 必要浏览器 API、支持格式、文件大小上限、资源等级与估算。
- Worker 执行适配器、依赖列表、测试入口、双语文案键。
- 页面能力与结果类型声明。

数据库只能控制启用状态、分类展示、排序和管理员编辑的展示元数据；不能创建不存在的工具实现。注册表、Seed、数据库三方一致性由 CI/部署检查。

## 版本化 TypeScript 契约
- 共享 `ToolDefinition` / `ToolAdapter` 契约置于独立 contracts 包。
- 每个工具必须实现注册描述、输入校验、执行适配器、进度事件、取消协议、错误映射与结果提交。
- 契约变更必须有版本与兼容性测试；工具不得私自改变任务状态机、文件资产模型或错误结构。
- 新工具接入需通过契约测试，不得绕过共享任务/文件/API 核心。

## 统一页面骨架
1. 标题与简介。
2. 文件输入区：拖放/选择、队列、格式/大小提示、移除与校验结果。
3. 主工作区：按工具类型呈现参数、预览和操作。
4. 任务区：状态、进度、耗时、取消、失败原因与重试。
5. 结果区：结果列表、预览、基本信息、下载/批量操作；源文件下可展开查看对应处理结果与元数据。
6. 底部规范：依赖/开源致谢，作为页面内最后一个板块，不直接塞进全站页脚。

不适用区域可按统一规则隐藏或折叠，不能改变剩余区块的语义与顺序。

## 开发要求
- 工具专属依赖按需引入；重型 WASM/模型/媒体引擎动态导入。
- 所有文件处理默认在浏览器本地执行；不得将用户文件、结果或任务数据上传服务器。
- 每个工具声明输入限制、资源预算、浏览器 API 要求、错误代码、测试用例和开源许可证。
- 页面布局与组件优先复用；禁止复制共享核心逻辑。
